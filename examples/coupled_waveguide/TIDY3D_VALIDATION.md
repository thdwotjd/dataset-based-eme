## Interpret the first results

Check the raw input Ey center against the target, the input E/H mismatch after phase and power alignment, backward flux, and the reconstructed/native signed flux ratio at both planes. Tidy3D's mode monitor separates directions and supplies the modal fields used for forward reconstruction. Recorded raw E/H shows what the reconstruction misses. Check modal power against integrated flux before trusting the incident denominator or output projection. The output projects reconstructed forward E/H onto the same isolated references as DREME; neither solver's coupled mode indices are reported as bus/ring powers. Channel entries are squared coefficients of 1 W references; the coherent total includes cross terms. The baseline uses DREME P0 and measured Tidy3D forward input power, while the mapped launch uses DREME P1 and measured Tidy3D forward input power. The comparison includes both DREME denominators, its guided-only readout on the same propagated vector, and the 17-node result.

Use the uniform case to identify launch/plane discrepancies first. Then use the moving case and the 17→33 gap sampling comparison to decide what to refine. The initial pair does not set an acceptance tolerance. The completed local comparisons, mathematical audit and remaining accuracy limits are recorded in [the Commit 6 results](../results/coupled_waveguide/README.md).

The basis export is local and optional to repeat. If the supplied NPZ is missing, use `lumeric` with the existing Lumerical v251 API and run `python -m examples.coupled_waveguide.tidy3d_reference DATASET OUT.npz --mode-api-dir MODE_API`. It re-solves only the endpoint coupled modes and two isolated guides and rejects field products that cannot be reconciled with the stored generation.
